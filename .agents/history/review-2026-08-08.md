## Gate assessment

**Phase 0B's exit criteria are met.** The benchmark contract is reproducible,
the three codec modes are testable, the native frame writes and validates
bounded raw blocks through direct Rust IO (including the native-codec-ID test
in [reader.rs](src/rust/src/container/reader.rs)), and adding logical records
will not force a redesign of codec identification, trailer discovery, or
directory bounds.

[test-correctness.R](tests/testthat/test-correctness.R) is genuinely broad —
closures, environments, cycles, shared references, S4, bytecode, and `CE_BYTES`

## Confirmed bugs

### 1. `.Rbuildignore` gap ships 62 MB of Cargo artifacts

[.Rbuildignore:11](.Rbuildignore#L11) has `^src/rust/target$`, which is anchored
and does not match `src/rust/target 2/` — the macOS duplicate directory present
in the working tree.

Verified: `R CMD build` produces a **21 MB tarball containing 385 entries under
`src/rust/target 2/`**, along with many `storing paths of more than 100 bytes is
not portable` tar warnings.

`^src/Makevars [0-9]+$` was already added for exactly this class of macOS
duplicate; the rust target case was missed. Separately, `CLAUDE.md` ships as a
dereferenced 9.7 KB regular file, because `.Rbuildignore` covers `^AGENTS\.md$`
but not the symlink pointing at it.

**Fix**

- Add `^src/rust/target( [0-9]+)?$` and `^CLAUDE\.md$` to `.Rbuildignore`.
- Add a ` [0-9]*` duplicate pattern to [src/.gitignore](src/.gitignore).
- Delete the stray `src/rust/target 2/` and `src/Makevars 2|3|4` from the tree.

### 2. `rdz_info()` reports truncated names while claiming `truncated = FALSE`

[R/serialize.R:143](R/serialize.R#L143) and [R/serialize.R:157](R/serialize.R#L157)
compute the truncation flag from a **byte** threshold (`> 256`), but
[`bound_rdz_strings()`](R/serialize.R#L178) truncates to `bytes %/% 4` = 64
**code points**. Any ASCII name between 65 and 256 characters is silently cut
and then reported as complete.

Verified: a 70-character attribute name is returned as 64 characters with
`truncated = FALSE`; a 100-character class name behaves the same way. The
existing test in [test-public-api.R](tests/testthat/test-public-api.R) uses
1000-character names, which clear the byte threshold and hide the window.

Because the synopsis's entire contract in
[metadata-access.md](../metadata-access.md) is to label what it does not
know, this is the worst possible place for a false negative.

**Fix**: derive the flag from the actual result — compare the bounded value
against the original with `identical()` — instead of maintaining a parallel
heuristic that can disagree with the bounding function.

### 3. WITHDRAWN — `names(attributes(x))` does not materialize attribute values

Originally raised as a write-path allocation problem at
[R/serialize.R:153](R/serialize.R#L153), on the theory that `attributes()` builds
every attribute value and expands a data frame's compact row names. **That was a
measurement error and the finding does not stand.**

The original evidence was `object.size(attributes(df)$row.names)` reporting
19.1 MB for a 5-million-row frame. `object.size()` reports the *notional*
materialized size of an ALTREP compact sequence, not the memory actually
allocated. Measured properly:

```
bench::bench_memory(a <- attributes(data.frame(x = 1:5e6)))$mem_alloc  # 0 bytes
.Internal(inspect(a$row.names))  # INTSXP ... 1 : 5000000 (compact)
```

Compact row names come back as an ALTREP compact sequence, and every other
attribute value is shared by pointer rather than copied — `identical()` on the
address confirms it for a 5-million-element `names` attribute. `attributes()`
allocates only a short list of pointers plus the character vector of names, so
the cost is O(number of attributes) and does not scale with object size.

Recorded here rather than deleted so the question is not reopened.

## Format decisions cheaper to settle now than after Phase 1

### 4. Block-header stored length is `u32`; the directory entry's is `u64`

Compare [container-format.md:83](../container-format.md#L83) with
[container-format.md:129](../container-format.md#L129); the two are checked
against each other at [reader.rs:291](src/rust/src/container/reader.rs#L291).

Harmless under `MAX_BLOCK_SIZE = 64 MiB`, but once compression makes
`stored_len != decoded_len` the asymmetry becomes real. Pick one width.

Related: [writer.rs:146](src/rust/src/container/writer.rs#L146) performs an
unchecked `entry.stored_len as u32` truncating cast, on the shared
`write_container` path that Phase 1 will reuse.

### 5. The header's nominal block size is bounds-checked but never cross-validated

[reader.rs:103](src/rust/src/container/reader.rs#L103) bounds the field, but
nothing validates it against the actual blocks — yet `rdz_info()$block_size`
reports it to the user as fact. Either validate it (all blocks but the last
must equal it) or document it as informational.

### 6. `synopsis_error` exists only on the failure path

Compare [R/serialize.R:127](R/serialize.R#L127) with
[R/serialize.R:161](R/serialize.R#L161). `container-format.md` presents
`synopsis_error` as the flag consumers check, but on the success path the field
is absent — `NULL` rather than `FALSE` — and the two lists differ in length.
Emit it unconditionally so the synopsis has a stable schema.

## IO semantics

### 7. "Atomic" here means crash-visible, not crash-durable

[writer.rs:91](src/rust/src/container/writer.rs#L91) calls `file.flush()`, which
is a no-op for `std::fs::File`, and there is no `sync_all()` before the rename in
[atomic_file.rs:62](src/rust/src/atomic_file.rs#L62). A crash can therefore leave
a renamed but unflushed file.

This is a defensible tradeoff that most serializers make, but a package whose
pitch is integrity should state it explicitly rather than let `flush()` imply
otherwise. Consider an opt-in sync mode.

### 8. Replacement widens file permissions

The temporary file is created at the default mode and umask
([atomic_file.rs:33](src/rust/src/atomic_file.rs#L33)) and then renamed over the
destination, so replacing a `0600` `.rdz` file yields a `0644` one. `saveRDS`
preserves the existing mode.

### 9. The cross-device / sharing-violation fallback in `commit()` is not atomic

In the fallback branch the destination does not exist between the two renames,
and a crash there strands a `.name-rdz-N.backup` file. Worth documenting as a
known limitation of the non-`rename(2)` path.

## Performance headroom on the path being measured

### 10. The read path copies the payload three times

[reader.rs:57-65](src/rust/src/container/reader.rs#L57-L65) allocates and
zero-fills a per-block `Vec`, reads into it, then `extend_from_slice` into
`payload`. [lib.rs:36](src/rust/src/lib.rs#L36) then copies that buffer into a
fresh R raw vector, and `unserialize()` reads it again.

Two of the three are removable:

1. Read directly into `payload`'s tail — `resize` then
   `read_exact(&mut payload[start..])`, and CRC that subslice.
2. Better, allocate `OwnedRawSexp::new(len)` up front and read blocks into
   `as_mut_slice()`. Both APIs are confirmed present in savvy 0.10.2.

[current-state.md](../current-state.md) names "a raw-buffer allocation, file
pass, and mandatory CRC scan" as the reason RDZ loses to uncompressed base R on
simple atomic payloads. This is the cheapest part of that to reclaim, and it is
independent of the streaming callback bridge deferred to Phase 8.

Also: the seek at [reader.rs:56](src/rust/src/container/reader.rs#L56) is
redundant, because `validate_block_header` leaves the cursor exactly at
`payload_offset`.

## Coverage gaps

### 11. The empty-payload branch is unreachable from R and untested in Rust

[writer.rs:76-78](src/rust/src/container/writer.rs#L76-L78). `serialize()` never
returns zero bytes, so R cannot reach this path, and no Rust test passes an empty
slice. Tracing it by hand shows it does round-trip correctly, but the reader's
`block_count == 0` rejection and its zero-length block handling go unexercised —
and a native codec writing an empty vector will be the first thing to hit them.

### 12. No `\examples{}` in any exported function

None of `write_rdz`, `read_rdz`, or `rdz_info` has an examples block, so
`R CMD check` runs no example code at all. CRAN will also require them.

### 13. Minor

- [src/rust/Cargo.toml](src/rust/Cargo.toml) declares `version = "0.1.0"` while
  [DESCRIPTION](DESCRIPTION) declares `0.0.0.9000`.
- `class(info) <- "rdz_info"` is set in [R/serialize.R:95](R/serialize.R#L95)
  with no corresponding `print` method.

## Phase 1 readiness

Two structural items are better resolved before the logical vertical slice than
during it.

**The eligibility interface will bake in a double traversal.**
`rdz_select_codec()` computes native eligibility and discards it
([r_adapter.rs:56](src/rust/src/r_adapter.rs#L56)), returning only a codec name.
A native write will therefore traverse the SEXP twice — once to decide, once to
encode. Fusing them into a single Rust call that returns either an encoded result
or the distinguished unsupported-native outcome avoids committing to the double
traversal in the interface shape.

**The object and attribute directory entries exist only as prose.** They are
described in [container-format.md](../container-format.md) but have no Rust
structs, and the reader hard-rejects nonzero counts
([reader.rs:197](src/rust/src/container/reader.rs#L197)). "Reserved" currently
means "documented". Phase 1 is the first real test of whether the 48-byte object
entry and 32-byte attribute entry are the right shape.
